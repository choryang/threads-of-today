# 내 하루에 닿은 사람들

하루 한 번 저녁에 1분. 오늘의 마음을 고르고 오늘 손에 닿은 물건을 고르면, 물건을 **재료로 분해**한 경로 위에서
같은 마음의 하루를 보낸 한 사람을 만나 그 사람의 이야기를 읽고 한마디를 건넨다. '걷기' 탭에서는 물건이 지나온 길 전체를 따라 걷는다.
화면과 흐름의 기준은 `docs/redesign/README.md`, 파일 구조는 `CLAUDE.md`.

## 바로 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

API 키 없이도 동작한다. 이때는 로컬 매칭(대표 물건·물건 사전·동의어·오타·합성어·재료 별칭)과 공유 캐시로만 분해하고, 사진 인식과 '아무 말이나 잇기'는 꺼진다.
Upstash 없이 `npm run dev`로 띄우면 캐시·요청 제한·진행 상황 저장은 `.data/kv` 파일에 저장된다.

```bash
npm test               # 매칭·병합·닉네임·복구 코드 단위 테스트
npm run check:data     # 데이터 무결성 검사
npm run dict:build -- --dry-run   # 물건 사전 만들기 (요청 예시와 예상 비용만)
npm run cache:export   # AI 캐시를 조회 수 순으로 data/review/cache.csv에, 준비 중 재료 집계를 missing-live.csv에 (커밋하지 않음)
```

## Vercel 배포

1. 이 폴더를 GitHub 저장소로 올린다.
2. Vercel에서 저장소를 Import 한다. 프레임워크는 Nuxt로 자동 인식된다. 빌드 설정은 기본값 그대로 둔다.
3. 프로젝트의 Storage(또는 Marketplace) 탭에서 **Upstash Redis**를 만들어 이 프로젝트에 연결한다.
   연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 환경 변수에 자동으로 들어간다.
   (Upstash 콘솔에서 직접 만든 DB라면 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`을 넣어도 된다.)
4. Settings → Environment Variables에 추가한다.

   | 변수 | 필수 | 설명 |
   | --- | --- | --- |
   | `NUXT_ANTHROPIC_API_KEY` | 선택 | Claude API 키. 없으면 로컬 매칭과 캐시만 쓴다 |
   | `NUXT_ANTHROPIC_MODEL` | 선택 | 기본 `claude-haiku-5-5` |
   | `KV_REST_API_URL` / `KV_REST_API_TOKEN` | 권장 | Upstash 연결 시 자동. 없으면 캐시·요청 제한이 인스턴스 메모리로만 동작하고, 진행 상황 서버 저장(다른 기기에서 이어 하기)은 꺼진다 |
   | `NUXT_AI_DAILY_LIMIT` | 선택 | IP별 하루 AI 호출 한도. 기본 20 |
   | `NUXT_IP_SALT` | 권장 | 요청 제한 키에 쓰는 IP 해시의 소금값. 아무 긴 문자열 |
   | `CRON_SECRET` | 권장 | Vercel Cron(`/api/cron/cleanup`, 매일 서울 새벽 4시)이 보내는 Bearer 토큰. 없으면 청소가 늘 거절되어 이틀 지난 `meet:*`·`thanks:day:*` 키가 쌓인다. 16자 이상 무작위 문자열 |
   | `MEET_SNAPSHOT_MINUTES` | 선택 | 모두의 오늘 숫자를 다시 세는 간격(분). 기본 30, 1~1440. CDN 캐시(`s-maxage`)와 기기의 다시 묻기 간격도 이 값을 따른다. 짧을수록 숫자가 빨리 바뀌지만 다시 셀 때마다 Upstash 명령이 약 227개 든다 |
5. Deploy. 로컬에서 운영 저장소에 붙여 보려면 `vercel env pull .env`로 변수를 받아 온다.

요청 하나에 출력 토큰은 최대 500개로 제한돼 있다.

## AI 호출 줄이기

텍스트 입력은 아래 순서로 찾고, 앞에서 잡히면 거기서 끝난다.

1. **로컬 매칭** (`shared/match`): 정규화 → 대표 물건·물건 사전 정확 일치 → 동의어 → 오타(자모 편집 거리) → 합성어 분해 → 재료 별칭 부분 일치
2. **공유 캐시** (Upstash): 예전에 누군가 AI로 분해한 입력이면 그 결과를 쓴다. 정규화한 입력이 키
3. **Claude**: IP별 하루 한도(`NUXT_AI_DAILY_LIMIT`) 안에서만. 결과는 캐시에 저장. 하루는 한국 시간(Asia/Seoul) 자정에 바뀐다
   - 고유명사(회사·기관·브랜드·서비스·게임·장소, 사람 이름 빼고)면 재료로 나누지 않고 `proper`로 캐시한다. 걷기는 길 대신 `/api/whereis`로 Claude의 한마디와 입력 그대로의 구글 지도 검색 링크를 보여 준다(지도 API는 부르지 않는다). 한마디는 입력 키로 캐시

### 아직 여정이 없는 주재료

주재료가 재료 목록에 없으면 AI는 다른 작물·과일·차로 대신하지 않고(망고주스 → 바나나 ✕), 실제로 들어가는 재료만 고른 뒤
목록에 없는 주재료 이름을 `missing_ingredients`로 따로 보고한다. 화면에는 "망고의 여정은 아직 준비 중이에요"를 보여 주고,
나머지 재료가 있으면 그 재료로만 여정을 떠난다. 실제로 들어가는 재료가 하나도 없으면(둥굴레차) 여정을 떠날 수 없다.
주재료가 준비 중인데 포장재(plastic, pulp, glass)만 남아도 여정을 떠날 수 없다(보리차가 페트병 여정만 떠나지 않게). 생수처럼 준비 중 재료가 없는 포장재 물건은 그대로 떠난다.

준비 중 재료 이름은 `shared/data/missing-names.ts` 규칙으로 정리한다(`resolveMaterials`).
같은 재료의 다른 이름은 대표 표기로 합치고(동태·황태 → 명태, 곶감 → 감), 재료가 아닌 것은 빼고(비타민, 향료),
이미 있는 재료의 한 형태는 그 재료로 옮긴다(찹쌀 → 쌀, 홍차 찻잎 → 녹차). 규칙을 바꾸면 `npm run dict:build -- --refresh`로 사전에 다시 적용한다.

- 사전·캐시·Claude 어느 경로로 나왔든, 사용자에게 "준비 중"을 보여 줄 때마다 Upstash 정렬 집합 `mdp:stats:missing`에 재료 이름별로 1씩 센다.
- `npm run cache:export`가 이 집계를 `data/review/missing-live.csv`로 뽑는다.
- 사전 만들기는 사전 전체의 `missing`을 많이 나온 순서로 `data/review/missing.csv`에 집계한다. 새 재료를 고를 때 둘을 함께 본다.

사진은 입력 자체를 캐시할 수 없어서 Claude를 먼저 부르고, 알아본 물건 이름으로 사전과 캐시를 다시 찾는다. 없으면 이름을 키로 캐시에 저장한다.
캐시 항목에는 조회 수(`hits`), `firstSeen`, `source: 'ai'`가 남는다. `npm run cache:export`로 뽑아 검토하고 좋은 것은 사전으로 옮긴다.

물건의 한마디(voice)에는 닉네임이 들어가지 않는다. 사전과 캐시를 모든 사용자가 같이 쓰므로 AI에는 닉네임을 보내지 않고,
대사에는 `{name}` 자리표시자만 쓰게 한 뒤 화면에서 닉네임을 끼워 넣는다. `{name}`은 부르는 말("{name}, …")로만 허용한다.

## 진행 상황 저장과 다른 기기에서 이어 하기

- 진행 상황의 원본은 그대로 브라우저 localStorage(`my-day-people:v1`)다.
- 오늘 기록이 처음 생긴 뒤 동기화할 때 서버가 익명 id, 기기 비밀값, 복구 코드(예: `바다-연필-4827`)를 발급한다(`hasProgress`). 걷기만 하는 사람은 서버에 기록을 만들지 않는다.
  이 기기 정보는 `my-day-people:profile`에 따로 저장한다.
  - 복구 코드는 두 글자 낱말 2개와 숫자 4개. 헷갈리는 0과 1은 쓰지 않는다. 띄어쓰기·하이픈은 있어도 없어도 된다.
  - 복구 시도는 IP별 시간당 10번으로 제한한다.
- **앱을 열 때**와 **한마디를 건넬 때**만 서버와 동기화한다. 충돌하면 `shared/progress.ts`의 `mergeSaves`로 합친다.
  - 하루 기록(todays): 같은 날이면 한마디를 건넨 쪽
  - 예전 기획의 필드(카드·여정·마을 등)는 Save 모양을 지키려고 합치기만 하고 화면에서는 쓰지 않는다
- 복구 코드로 이어 하기(`/api/profile/restore`, `useSync().restore`)는 서버에 남아 있지만, 지금 화면에는 코드를 보거나 넣는 곳이 없다.
  코드를 입력한 기기에는 새 기기 비밀값이 발급되고(사용자당 최대 5대), 두 기기의 기록이 합쳐진다.
- 진행 기록이 없는 익명 사용자는 30일, 기록이 있으면 마지막 동기화부터 400일 동안 보관한다.

### 저장 키와 데이터 크기

| 키 | 값 | 보관 |
| --- | --- | --- |
| `mdp:user:{id}` | 메타(복구 코드, 기기 비밀값 해시, 연결 계정) + 진행 상황 | 30일(기록 없음) / 400일 |
| `mdp:code:{코드}` | id | 사용자와 같게 |
| `mdp:cache:text:{정규화한 입력}` | AI 분해 결과 + hits | 마지막 조회부터 180일 |
| `mdp:rate:…` | 요청 제한 카운터 (IP는 해시로만) | 1~2일 |
| `mdp:stats:missing` | 준비 중 재료 이름 → 요청 횟수 (정렬 집합) | 계속 |

사용자 한 명의 값 크기 (실측, JSON):

| 경우 | 크기 |
| --- | --- |
| 새 사용자 | 약 0.5KB |
| 보통 (카드 60장, 물건 80개, 15일 × 하루 3번) | 약 20KB |
| 많이 (카드 전부, 물건 500개, 30일 × 하루 4번) | 약 59KB |

서버는 200KB가 넘는 요청을 받지 않고, 하루 여정 60개·물건 2,000개를 넘는 기록은 버린다.

### 요청당 Redis 명령 수

| 요청 | 명령 | 내용 |
| --- | --- | --- |
| 분해: 로컬 매칭으로 잡힘 | 0 | |
| 분해: 캐시에 있음 | 2 | GET + SET(조회 수) |
| 분해: 캐시에 없음 → Claude | 4 | GET + INCR·EXPIRE(한 번에 보냄) + SET |
| 분해: 하루 한도 초과 | 3 | GET + INCR·EXPIRE |
| 분해: 사진 | 2~4 | INCR·EXPIRE + (사전에 있으면 끝) GET + SET |
| 분해: 결과에 준비 중 재료가 있음 | +1~3 | 위에 더해 재료마다 ZINCRBY(한 번에 보냄) |
| 첫 방문 (`POST /api/profile`) | 4~5 | INCR·EXPIRE + SET NX(코드) + SET(사용자) (+ 코드 보관 기간 SET) |
| 동기화 (`/api/profile/sync`) | 2~3 | GET + SET (+ 한 달에 한 번 코드 보관 기간 SET) |
| 이어 하기 (`/api/profile/restore`) | 5~6 | INCR·EXPIRE + GET(코드) + GET(사용자) + SET (+ 코드 SET) |

하루 세 번 여정을 하고 앱을 세 번 여는 사용자는 동기화만으로 하루 약 12~15개 명령을 쓴다. Upstash 요금제의 명령 수·용량 한도는 연결 전에 요금 페이지에서 확인할 것.

### 나중에 카카오·구글 로그인 붙이기 (아직 구현하지 않음)

익명 id는 그대로 두고, 로그인은 "id를 찾는 또 하나의 방법"으로 붙인다 (`server/utils/users.ts` 주석 참고).

- `mdp:account:{provider}:{subject}` → id 키를 추가하고, 연결한 계정을 사용자 값의 `accounts`에 적는다.
- 로그인한 계정 키가 없으면 지금 기기의 익명 id에 연결한다(진행 상황 그대로).
- 이미 다른 id에 연결돼 있으면 그 id로 갈아타고 두 진행 상황을 `mergeSaves`로 합친다.

## 오늘 흐름과 걷기

- 오늘 흐름: 마음 → 물건 → 같은 순간 다른 시각 → 그 사람의 오늘 → 한마디. 하루 한 번이고, 기록이 있으면 오늘의 결과를 보여 준다.
- 한 사람 고르기는 `shared/pick.ts`, 화면 문구는 `shared/today-text.ts`, 이야기는 `shared/data/stories.ts`(사용자가 쓴 문구라 고치지 않는다).
- 걷기(`/walk`): 물건이 지나온 길 전체(`shared/walk.ts`). 깨어 있는 사람 수, 형태 변화, 바다·하늘·땅 구간 거리, 일의 크기, 끝 요약.
  열 때 서버를 부르지 않는다. 고유명사를 넣으면 길 대신 한마디와 지도 검색 링크(`/api/whereis`).
- AI는 **어떤 재료로 나눌지만** 정한다. 길의 사실 정보는 모두 `shared/data`에 직접 작성한 데이터에서만 나온다.
- 모두의 오늘: 실을 묶으면 마음 id만 보내고(`/api/mood`), 스냅샷이 30분마다 마음 8개 수를 센다.
- 공유: 오늘의 실 링크(`/t`, 30일)와 앱이 그린 카드 그림. 하루의 한 줄과 직접 쓴 한마디는 담지 않는다.

## 재료·사람 추가하기

출발지 변형은 재료에 `originHead`(기본 경로 앞에서 몇 명을 바꿀지)와 `origins`(첫 번째는 기본 경로와 같게)를 적는다.
새 사실을 넣을 때는 사람 카드 위에 출처를 주석으로 남긴다. 숨은 만남은 `shared/data/journey-extras.ts`의 `HIDDEN_RULES`에, 이야기는 `EVENTS`에 추가한다.


1. `shared/data/people.ts`에 사람을 추가한다.
2. `shared/data/materials.ts`에 재료와 `stages`(사람 id 순서), 퀴즈를 추가한다.
3. `npm run check:data`로 빠진 연결이나 얻을 수 없는 카드가 없는지 확인한다.

재료를 추가하면 Claude가 고를 수 있는 목록에도 자동으로 들어간다.

## 출시 전에 확인할 것

- 직접 쓴 여정과 이야기는 게임이라 허구가 조금 섞여도 된다(화면에 "대표 경로 예시" 고지를 붙이지 않는다). 실제 자료에서 가져온 사실에는 출처 주석을 남긴다.
  AI가 만든 문구(twist, voice)에는 나라·숫자 같은 사실처럼 보이는 정보가 섞이지 않게 하는 원칙은 그대로다(`shared/safety.ts`).
- **출발지 가중치는 게임용이다.** 한 재료의 출발지가 고루 나오게 정했다
  (2곳 3:2, 3곳 2:1:1, 커피 4곳 1:1:1:1. 가장 드문 출발지도 25% 이상). 실제 생산·수입 비중은 각 재료 주석에 남겨 두었다.
  그래서 화면이나 홍보 문구에서 "많이 들어오는 나라 순" 같은 표현을 쓰지 않는다. `scripts/update-origins.ts`(관세청 수출입실적)는 실제 비중을 참고할 때만 쓴다.
- 브라질 커피 카드(`br-coffee-farmer`, `br-santos-coffee`)의 근거는 `shared/data/people.ts` 주석의 Conab·Cecafé 인용 기사다. 원 자료(Conab 작황 조사, Cecafé 월간 보고서)로 한 번 더 확인하면 좋다.
- 팥·감자·무·사과·보리·오징어·토마토·포도·고구마·메밀 10개 재료의 사실과 출처는 `shared/data/people.ts` 주석에 있다. 주석에는 실제 생산·수입 통계를 남겼고,
  출발지 가중치는 게임용이다. 수입 경로의 항구·배 종류는 확인하지 못해 넣지 않았다.
- 물건 사전(`shared/data/dictionary.json`)은 AI가 만든 결과다. `data/review/dictionary.csv`를 훑어보고 재료가 어색한 항목은 고치거나 지운다.
  새 재료를 추가하면 `npm run dict:build -- --redo-missing 팥,감자`로 그 재료가 `missing`에 들어 있는 항목만 다시 만든다.
- Upstash를 연결하지 않으면 AI 요청 제한이 서버 인스턴스마다 따로 세어져 느슨해지고, 다른 기기에서 이어 하기가 꺼진다.
- 사람 이름(`shared/data/names.ts`)의 출처는 나라마다 다르다. 베트남·방글라데시·사우디아라비아는 정부 통계가 없어 백과사전·신문·학술 자료로,
  필리핀은 통계청의 2월 29일 출생자 표로 확인했다. 더 나은 자료를 찾으면 바꾼다.
- 배포 전 체크리스트:
  - [ ] **Upstash 종량제(Pay as you go) 전환과 월 예산 상한.** 무료 요금제 한도를 넘으면 명령이 거절되어 동기화·모두의 오늘이 멈춘다.
        사용자 1,000명/일이면 하루 약 11만 명령(월 약 330만, 스냅샷 30분 기준)으로 예상한다. Upstash 콘솔 → 데이터베이스 → Usage/Plan에서 종량제로 바꾸고,
        Budget(월 예산 상한)을 정해 둔다. 상한에 닿으면 무료 한도처럼 요청이 막히니 Usage를 처음 몇 주는 직접 본다
  - [ ] **`CRON_SECRET` 환경 변수.** Production에 16자 이상 무작위 문자열로 넣고 다시 배포한다. 없으면 `/api/cron/cleanup`이 늘 401을 돌려줘
        이틀 지난 `mood:*` 키가 쌓인다(이 키들은 EXPIRE 없이 청소에 맡긴다).
        배포 뒤 Vercel → Settings → Cron Jobs에 `/api/cron/cleanup`(`0 19 * * *`, 서울 새벽 4시)이 보이는지, Run으로 한 번 돌려 함수 로그에 `[cron] cleanup`이 남는지 본다.
        헤더 없이 `curl https://<도메인>/api/cron/cleanup`을 부르면 401이어야 한다
  - [ ] **Vercel 함수 지역 `icn1`(서울).** Settings → Functions → Function Region을 Seoul(icn1)로 바꾼다. 기본값(미국 동부)이면 한국 사용자 요청과
        Upstash 왕복이 모두 태평양을 건넌다. Upstash 데이터베이스 지역도 서울에 가까운 곳인지 함께 확인한다

## Upstash 연결 후 확인할 것

Vercel에서 Upstash Redis를 연결한 다음 아래 순서로 확인한다. 키는 Upstash 콘솔의 Data Browser에서 `mdp:`로 검색하면 보인다.
`<도메인>`은 배포 주소다.

**0. 연결 자체**

- [ ] Vercel → Settings → Environment Variables에 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 Production(필요하면 Preview도)에 들어가 있다
- [ ] `NUXT_IP_SALT`를 긴 무작위 문자열로 넣었다 (바꾸면 진행 중인 요청 제한 카운터가 새로 시작된다)
- [ ] 환경 변수를 넣은 **뒤에** 다시 배포했다 (이미 만든 배포에는 새 변수가 들어가지 않는다)
- [ ] 첫 화면을 열었을 때 Vercel 함수 로그에 `[profile] … failed`, `[decompose] cache write` 오류가 없다

**1. 캐시 저장·조회** (`NUXT_ANTHROPIC_API_KEY`가 있어야 확인할 수 있다)

- [ ] 사전에 없을 법한 입력(예: 평소 안 쓰는 긴 물건 이름)을 '직접 쓰기'로 넣는다. 응답(개발자 도구 Network의 `/api/decompose`)에 `"source":"ai"`가 있고 `via`는 없다
- [ ] Data Browser에 `mdp:cache:text:{정규화한 입력}` 키가 생겼고 `hits: 1`, `firstSeen`, `source: "ai"`가 들어 있다. TTL은 약 180일(15,552,000초)
- [ ] 같은 입력을 **다른 브라우저나 기기**에서 다시 넣으면 응답에 `"via":"cache"`가 붙고, 키의 `hits`가 2로 오른다
- [ ] 띄어쓰기만 다르게 넣어도 같은 키로 잡힌다
- [ ] 대표 물건(예: "아메리카노")을 넣으면 `"source":"local"`이고 캐시 키가 새로 생기지 않는다 (Redis 명령 0개)

```bash
curl -s -X POST https://<도메인>/api/decompose -H 'content-type: application/json' -d '{"text":"<시험할 입력>"}'
```

**2. 요청 제한**

- [ ] Preview 배포에서 `NUXT_AI_DAILY_LIMIT=2`로 두고, 캐시에 없는 새 입력 3개를 차례로 넣는다. 세 번째에 직접 쓰기 아래 "오늘은 직접 쓰기를 다 썼어요. 위 물건은 계속 고를 수 있어요" 안내가 나오고, 물건 타일은 계속 고를 수 있다
- [ ] `mdp:rate:ai:{날짜}:{IP 해시}` 키 값이 3이고 TTL이 약 2일(172,800초)이다. 키에 IP가 그대로 들어 있지 않다
- [ ] 한도를 넘긴 뒤에도 대표 물건·캐시에 있는 입력은 그대로 분해된다

**2-1. 준비 중 재료 집계**

- [ ] 주재료가 목록에 없는 물건(예: 망고주스)을 넣으면 화면에 "망고의 여정은 아직 준비 중이에요"가 나오고, 응답에 `"missing":["망고"]`가 있다
- [ ] Data Browser의 `mdp:stats:missing`(정렬 집합)에서 `망고`의 점수가 1 오른다. 같은 입력을 다시 넣어(캐시) 또 오른다
- [ ] `npm run cache:export`를 Upstash 변수와 함께 돌리면 `data/review/missing-live.csv`에 같은 숫자가 나온다
- [ ] 다른 네트워크(예: 휴대폰 데이터)에서는 따로 센다
- [ ] 날짜는 한국 시간(Asia/Seoul, `seoulDateKey`) 기준이다. 한국 시간 자정이 지나면 키의 날짜가 바뀌고 한도가 새로 시작된다
- [ ] 확인이 끝나면 `NUXT_AI_DAILY_LIMIT`을 원래 값(기본 20)으로 되돌린다
- [ ] 복구 코드 시도 제한: 틀린 코드를 11번 넣으면 11번째에 "잠시 후 다시 시도해 주세요."가 나온다 (`mdp:rate:restore:…`, 시간당 10번)

**3. 진행 상황 동기화**

- [ ] 새 브라우저(시크릿 창)로 처음 열면 `/api/profile`이 불리지 않는다(걷기만 해도 마찬가지)
- [ ] 오늘 흐름에서 한마디를 건네면 `/api/profile` 응답이 `ok: true`이고 id·복구 코드가 온다. `reason: "unavailable"`이 오면 Upstash 변수가 안 읽힌 것이다
- [ ] `mdp:user:u_…`, `mdp:code:{복구 코드}` 키가 생겼고, `save.todays`에 오늘 기록이 있다. TTL은 약 400일
- [ ] 앱을 새로 고쳐도 `/api/profile`이 다시 불리지 않고 `sync`만 불린다 (localStorage `my-day-people:profile` 유지)
- [ ] Data Browser에서 사용자 값 크기가 README의 실측(새 사용자 약 0.5KB)과 크게 다르지 않다

**4. 복구 코드로 이어 하기** (지금은 화면이 없어 API로만 확인한다)

- [ ] 코드를 띄어쓰기로 넣거나(`바다 연필 4827`) 하이픈 없이 넣어도 찾는다
- [ ] 없는 코드를 넣으면 "코드를 찾지 못했어요…" 안내가 나온다
