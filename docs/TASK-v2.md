# v2 작업 지시서: AI 호출을 줄이면서 답변은 더 다양하게

먼저 `CLAUDE.md`를 읽고 원칙을 지켜 줘. 목표는 **AI 호출을 "사전에도 캐시에도 없는 처음 보는 입력"에만 쓰는 것**, 그리고 **AI 없이도 매번 다르게 느껴지는 여정**이다.

단계 순서대로 진행하고, 각 단계가 끝날 때마다 `npm run build`와 `npm run check:data`를 통과시킨 뒤 커밋해 줘. 판단이 갈리는 지점(외부 서비스 선택, 비용이 드는 실행)은 진행 전에 나에게 물어봐 줘.

---

## 0단계. 빌드 확인

- `npm install && npm run build`를 돌리고 나오는 오류를 모두 고친다.
- `npm run dev`로 띄워 홈 → 골라 보기 → 여정 끝까지 → 결과 카드 저장까지 한 번 직접 확인한다.
- 고친 내용은 짧게 정리해서 알려 줘.

## 1단계. AI 없는 매칭 강화 (원래 3번)

`shared/match/` 모듈로 분리하고 `matchLocal`을 대체한다. 순수 함수로 만들고 서버와 클라이언트 양쪽에서 쓸 수 있게 한다.

해석 순서 (앞에서 잡히면 거기서 끝):
1. 정규화: 공백·특수문자 제거, 소문자, 흔한 수식어 제거("편의점", "오늘", "한 잔", "하나" 등 목록으로 관리)
2. 대표 물건·사전 항목의 이름/별칭과 **정확 일치**
3. 동의어 사전(`shared/data/synonyms.ts`): 핸드폰=휴대폰=폰, 쇠고기=소고기, 계란=달걀, 돈까스=돈가스 등
4. 오타 허용: 한글을 자모로 분해해 편집 거리 비교. 짧은 단어는 엄격하게(예: 길이 기준 임계값). '아메리까노' → 아메리카노
5. 합성어 쪼개기: 사전 단어로 가장 긴 것부터 매칭해 분해. '참치김치김밥' → 참치 + 김치 + 김밥. 두 개 이상 잡히면 각 항목의 재료를 합쳐 최대 5개
6. 재료 별칭 부분 일치(2글자 이상만)

반환값에 어느 단계에서 잡혔는지(`via`)를 넣어 디버깅할 수 있게 한다.

테스트(`node:test` 또는 vitest, 가벼운 쪽으로)에 최소 이 사례를 넣는다:
- '참치김치김밥' → tuna, chili, cabbage, rice 포함 / 대표 물건 '참치캔'으로 잡히면 실패
- '김치' → laver 미포함, '라면' → cotton 미포함, '지하철' → 매칭 없음
- '아메리까노' → 아이스 아메리카노, '갤럭시 핸드폰' → 스마트폰 계열
- 'ㅁㄴㅇㄹ' → 매칭 없음

## 2단계. 미리 만드는 물건 사전 (원래 1번)

`scripts/build-dictionary.ts`를 만든다. **스크립트만 만들고 실제 API 실행은 내가 확인한 뒤에 한다.**

- 입력 시드: `data/seeds/items.txt`(흔한 물건·음식·생활용품·전자기기, 한 줄에 하나), `data/seeds/words.txt`(월요일, 비, 시험, 고양이처럼 물건이 아닌 일상 단어).
  - 시드 목록은 네가 직접 작성해 줘. 우선 물건 1,000개, 단어 200개 정도. 중복·너무 특수한 브랜드명은 빼고.
- Claude **Message Batches API**로 처리한다(실시간 API보다 저렴). 모델은 `claude-haiku-5-5`. 프롬프트와 도구 스키마는 `server/utils/decompose.ts`의 것을 재사용하되, voice는 한 개가 아니라 **3~5개 배열**로 받는다.
- 결과 검증: `sanitizeMaterialIds`로 걸러 재료가 0개면 버린다. voice에 숫자·국가명이 들어가면 버린다.
- 출력: `shared/data/dictionary.json` (`{ key, name, aliases, materialIds, twist?, voices[] }[]`), 그리고 사람이 훑어볼 수 있는 `data/review/dictionary.csv`.
- 옵션: `--dry-run`(요청 본문만 출력하고 비용 추정), `--limit N`, `--resume`(배치 id로 결과만 다시 받기).
- 실행 전 예상 토큰과 비용을 출력하고 확인을 받는다.
- 앱은 dictionary.json을 1단계 매칭의 사전으로 쓴다. 같은 물건을 다시 넣으면 voices 중 하나를 무작위로 보여 준다.
- 사전 크기가 커져도 클라이언트 번들이 무거워지지 않게, 사전 조회는 서버 API에서 하거나 지연 로딩한다. 어느 쪽이 나은지 근거와 함께 골라 줘.

(선택) 식품안전나라 품목제조보고(원재료) API로 가공식품 원재료를 받아 규칙으로 재료에 연결하는 스크립트. API 키가 필요하니 구조만 잡고 실행은 보류.

## 3단계. 공유 캐시와 요청 제한 (원래 2번)

- Nitro `useStorage`로 캐시 계층을 만든다. 운영은 Upstash Redis(Vercel 마켓플레이스) 같은 KV, 로컬은 메모리나 파일 드라이버. 현재 Vercel에서 쓸 수 있는 방식과 unstorage 드라이버를 확인하고 나에게 제안한 뒤 진행해 줘.
- `/api/decompose` 흐름: 1단계 로컬 매칭 → 캐시 조회(정규화한 입력을 키로) → 없으면 Claude → 결과를 캐시에 저장.
  - 사진은 입력 자체를 캐시할 수 없으니, Claude가 알아본 물건 이름으로 사전·캐시를 한 번 더 조회하고 결과를 이름 키로 저장한다.
- 캐시 항목에는 `hits`(조회 수), `firstSeen`, `source: 'ai'`를 남긴다.
- `scripts/export-cache.ts`: 조회 수 높은 순으로 CSV 출력. 내가 검토하고 좋은 것을 사전에 옮길 수 있게.
- 요청 제한도 같은 저장소로 옮긴다: IP별 하루 AI 호출 20회(환경 변수로 조절). 초과하면 로컬 매칭 결과만 주고 친절한 안내 문구.
- 환경 변수와 Vercel 설정 방법을 README에 추가한다.

## 4단계. AI 없이 다양해지는 여정 (원래 4번)

모두 데이터와 확률로만 만든다. 무작위는 **여정 id를 시드로** 써서 새로고침해도 같은 결과가 나오게 한다.

1. **출발지 변형**: 재료에 `origins` 배열을 추가할 수 있게 한다. 각 항목은 가중치와, 여정 앞부분(재배·채굴·수출항) 사람 id 목록. 예: 커피 = 에티오피아 / 콜롬비아 / 베트남.
   - 새 출발지의 사람 카드와 사실은 직접 작성하되, **확인한 사실만** 넣고 출처를 주석으로 남긴다. 확신 없는 국가는 넣지 않는다.
   - 가중치는 지금은 대략값으로 두고, 나중에 관세청 품목별·국가별 수출입실적 API로 갱신할 수 있게 `scripts/update-origins.ts` 뼈대만 만든다(실행 보류).
2. **여정 이벤트**: 단계 사이에 낮은 확률로 짧은 장면을 보여 준다. "항구가 붐벼 하루 늦게 출발했어요"처럼 **특정 날짜·실제 사건을 주장하지 않는 연출**로만 쓰고, 화면에 '이야기' 같은 표시를 붙여 사실 정보와 구분한다. 이벤트 20개 정도.
3. **숨은 만남**: 아주 낮은 확률로 여정 중에 숨은 레어 카드가 등장한다(예: 컨테이너선의 요리사, 항구의 검역관). 도감에서 '숨은 만남'으로 표시. check:data가 이 카드들도 얻을 수 있다고 인정하게 고친다.
4. 퀴즈도 재료별로 2~3개 중 하나가 나오게 늘린다(사실 확인된 것만).
